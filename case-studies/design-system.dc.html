One Figma system, ten brands, one set of decisions

A themeable Figma component library shared across ten pharmacy brands, so structure and behaviour are decided once and colour, type, and logo change per brand.

The problem

Ten client brands meant ten versions of every button, form, and drug card — and ten chances to get an accessibility detail wrong.

The approach

I built a themeable component library in Figma where structure and behaviour are shared and only colour, type, and logo change per brand.

Each component separates what can vary from what can't: a drug card's grid, spacing, and interaction states are locked, while colour, type family, and logo swap through a per-brand style set. New brands start from the same library rather than a duplicated file, and a fix, like a tap target that's too small or a contrast ratio that fails, gets made once at the component level and every brand that uses it inherits the correction on its next sync.

The outcome

Adopted by 10+ brands Shared component library

Design time per project dropped, handoff stopped being a translation exercise, and accessibility fixes now ship once instead of ten times.

Developers also gained a single source of truth to build against, instead of reverse-engineering ten slightly different versions of the same button.
