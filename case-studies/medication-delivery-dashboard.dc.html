Medication delivery dashboard

An internal dashboard giving pharmacy staff one view of order status, exceptions, and fulfilment timelines.

  • Product design
  • Data modelling
View in Figma / Adobe XD ↗

The problem

Pharmacy staff needed a single screen to track where every order stood, placed, packed, in transit, or held up, without switching between the fulfilment system, the courier portal, and a spreadsheet of exceptions.

The approach

I mapped every state an order actually passes through, placed, verified, packed, out for delivery, delivered, or held up on a missing prescription or payment issue, and designed the dashboard around that state model rather than around the underlying database tables.

Exceptions surface ahead of routine status, since a held-up order needs a person's attention and a delivered one doesn't. The layout favours density and scanability over decoration, built for staff who have this screen open all day.

Colour is used sparingly and consistently, one accent reserved only for states that need action, so staff can scan for that colour rather than reading every row. Filters let a pharmacist narrow to their own queue or a specific courier without losing the full list underneath, and every state change is timestamped so a held-up order shows how long it's been waiting, not just that it's waiting.

The outcome

One screen, one status model Order status, exceptions & fulfilment

Staff can see where every order stands and which ones need action without leaving the dashboard or cross-referencing a separate system.

The same state model now doubles as documentation: anyone new to the fulfilment process can read the dashboard and understand the workflow it represents.
